# MDK0401
# Главная цель
Организовать прозрачный, оперативный и достоверный учёт ТМЦ на складе, исключающий потери информации и снижающий влияние человеческого фактора.
# Ожидаемые результаты (KPI проекта)
Точность данных: Сокращение расхождений между фактическими остатками и данными в учётной системе до уровня < 1%.Скорость процессов: Сокращение времени проведения инвентаризации в 3–5 раз, а сборки заказов — на 30–40%.Оптимизация запасов: Снижение объёма неликвидных товаров и пересортицы на 25%.Финансовый контроль: Исключение неучтённых недостач и прозрачная интеграция с бухгалтерией.
Создание прозрачной, управляемой системы складского учёта, обеспечивающей современное снабжение производства и отгрузку клиентов без нарушения сроков и качества.

# Критерии успешного завершения 
Реальные процессы совпадают с системными: 100% складских операций (приёмка, перемещения, комплектация, отгрузка)
Контрольная сверка: Выборочная инвентаризация 50 случайных позиций ТМЦ показывает полное совпадение физического наличия с данными в программе.
Автономность персонала: Персонал склада выполняет ежедневные задачи без привлечения внешней проектной команды или интеграторов, руководствуясь внутренними инструкциями.
Документооборот: Бухгалтерия своевременно получает корректные первичные документы из складской системы без ручного дублирования.
# Модули складского учёта 
# Модуль приёмки (Inbound Management)
Отвечает за первичное поступление товара на склад. Сверка с планом: загрузка ожидаемых накладных от поставщиков из ERP-системы. Контроль факта: фиксация реального количества привезённого товара через сканирование штрихкодов. Маркировка: генерация и печать этикеток со штрихкодами (или QR-кодами) для неопознанного товара. Брак и расхождения: автоматическое формирование актов о недостаче или повреждении груза.
# Модуль адресного хранения и топологии (Slotting & Putaway)
Управляет виртуальной картой склада (стеллажи, полки, ячейки).Генерация адресов: присвоение каждой полке уникального индекса (например, A-04-02 — ряд A, стеллаж 4, полка 2).Умное размещение: алгоритм сам рассчитывает, в какую ячейку положить товар.
# Модуль управления запасами и остатками (Inventory Control)
Сердце системы, где хранится информация обо всех ценностях. Регистр остатков: отображение в реальном времени, сколько товара и в каких именно ячейках лежит. Специфический учёт: контроль сроков годности (приоритет выдачи старого товара — принцип FEFO), партий, серийных номеров и акцизных марок. Блокировка запасов: заморозка бракованного товара или резервирование позиций под оформленный, но еще не оплаченный заказ.
# Модуль отбора и комплектации (Picking & Packing)
Оптимизирует процесс сборки заказов для отгрузки. Маршрутизация: построение для сборщика оптимального пути по складу, чтобы он не ходил дважды по одному и тому же ряду. Методы сборки: поддержка группового отбора (один кладовщик собирает сразу несколько заказов) или зонального отбора (каждый собирает товар только в своей зоне). Контроль упаковки: финальная проверка собранного заказа по штрихкодам перед закрытием коробки.
# Модуль управления задачами (Task Manager)
Распределяет работу между сотрудниками. Очередь задач: сервер автоматически отправляет задания (например, «Иди прими товар» или «Собери заказ») на экраны терминалов сбора данных (ТСД) свободных сотрудников. Приоритеты: задачи на срочную отгрузку автоматически поднимаются вверх списка.
